## 2. 修 RUNBOOK（以你在 28o 执行日志里发现的问题为准）

1. **宿主机适配**：生产的 wp-cli 跑在容器里。统一定义成：
   `WPCLI="docker exec php php -d disable_functions= /usr/local/bin/wp --path=/var/www/html/www.packrivo.com/wordpress --allow-root"`
   - 注意区分宿主机路径（`/home/web/html/...`）和容器内路径（`/var/www/html/...`），每条命令都要写明在哪一侧执行。
   - `$PKG` 里的文件要进容器才能用，写清楚是用 `docker cp` 还是挂载。
2. **`$BACKUP` 固定下来**：第 1 步生成一次，写进 `/home/web/backups/CURRENT_LAUNCH` 文件。之后每个 SSH 会话从这个文件读取，不能再用 `$(date …)` 重新生成。
3. **备份路径和回滚路径要一一对应**：
   - mu 文件：`cp -a mu-plugins/. "$BACKUP/mu/"`（注意 `/.`），回滚时读 `$BACKUP/mu/<文件名>`；
   - i18n 同理：备份落在 `$BACKUP/i18n/<文件>`，回滚时按文件逐个覆盖，不能把整个目录塞进去；
   - 第 1 步的判据要逐项检查这些路径确实存在。
4. **首次安装的语义**：
   - 第 1 步不再要求备份子主题和插件（生产上没有），改为记录"安装前不存在"；
   - 第 4 步插件：`install` 之后执行 `plugin activate`，判据是 status 为 active；回滚 = `deactivate` 再 `delete`；
   - 第 5 步主题：`install` 之后执行 `theme activate packrivo-home-v4`，判据是 stylesheet 等于子主题；回滚 = `theme activate packrivo-static-bridge-1.2.38`，然后删除子主题目录；
   - 回滚命令不能用 `&&` 把"删除"和"恢复"串在一起，避免中间断掉、两头落空。
5. 第 6 行的版本号改成 WP 7.1.3。
6. 数据库备份：`db export` 写到 `$BACKUP/db.sql`，判据是文件非空且含 `CREATE TABLE`；第 9 步的"最后手段"读的就是这一份。
